# Спектр

«Спектр» объединяет построение рыночных кривых, оценку денежных потоков и анализ причин изменения NPV. Весь пользовательский сценарий доступен в одном браузере.

## Единый запуск

Запустите Docker Desktop или Docker Engine с Docker Compose 2.20+. Из корня репозитория выполните команду и откройте [Спектр на порту 8780](http://127.0.0.1:8780/).

```sh
make spectrum-up
```

Compose создаёт локальную БД, выполняет миграции, запускает API, worker и Go-сервис стрессов. В образ «Спектра» входят C++-ядро и встроенная сборка React. Порт 5173 для единого запуска не нужен. Порт интерфейса задаёт `SPECTRUM_DOCKER_PORT`, локальный порт API — `API_PORT`.

На Windows с Docker Desktop в режиме Linux-контейнеров используйте WSL 2 или PowerShell из корня репозитория.

```powershell
if (-not (Test-Path curves-module/.env)) {
    Copy-Item curves-module/.env.example curves-module/.env
}
docker compose -f docker-compose.yaml -f factor-analysis/compose.yaml up -d --build --wait spectrum
```

Если worker возвращает ошибку проверки сертификата MOEX, укажите путь к доверенному сертификату в `SPECTRUM_MOEX_CA` либо сохраните его в `factor-analysis/.local/certs/moex-ca.pem` и повторите `make spectrum-up`. Ручной команде Compose передайте также `-f factor-analysis/compose.moex-ca.yaml` и абсолютный путь в переменной окружения. Проверка TLS остаётся включённой. [Инструкция MOEX](https://www.moex.com/n106155?nt=112)

## Как связаны модули

| Команда | Модуль | Результат |
| --- | --- | --- |
| 1 | `calculator` | Нормализация исходного входа, C++ денежные потоки и отчёты по договорам |
| 2 | `curves-module` | Ставки MOEX, базовая и шесть стрессовых кривых, история Run ID |
| 3 | `factor-analysis` | Генератор истории сделок, оценка по дисконт-факторам команды 2, расчётный и ML-анализ, общий интерфейс и объяснения |

```text
MOEX → worker команды 2 → Go: базовая и стрессовые кривые → PostgreSQL → API
                                                                                ↓
Портфель → C++ команды 1 → договорные потоки → дисконтирование по дате и бакету
                                                               ↓
                                             NPV и семь сценарных PV → факторный анализ
```

React-компоненты модуля кривых монтируются внутри раздела «Кривые» при первом открытии. Shadow DOM изолирует стили. «Спектр» проксирует разрешённые маршруты `/api/v1/…` на настроенный внутренний API кривых. Запросы остальных разделов обрабатывает аналитический сервер. [Контракт и источники](integration/CONTRACT.md)

## Экраны и демонстрация

- **Анализ** показывает изменение метрики, вклады, остаток и проверку. В исследовании доступны динамика, Шепли, детализация CF, ML-диагностика и выгрузки.
- **Кривые** показывает ставки и расчёты команды 2. Выберите дату, откройте исходные ставки, настройте сценарии или выберите запуск в истории. Готовый стандартный рыночный запуск можно закрепить для оценки.
- **Сценарии** показывает PV портфеля по семи кривым, ΔPV и вклад сроков. Ссылка ведёт к сохранённому снимку, который применён в отчёте.
- **Портфель** объединяет генератор, параметры договоров, платежи C++ и результаты оценки.
- **Данные** принимает CSV для анализа зависимостей и ZIP снимков для расчётного анализа. Здесь доступны качество данных, экспорт источников, Run ID и контрольные суммы.

[Сценарий показа на 8–9 минут и резерв](integration/DEMO.md) · [Возможности до и после объединения](integration/CAPABILITIES.md) · [Результаты проверок](integration/UNIFIED_VERIFICATION.md)

## Автономный и самостоятельный запуск

Для показа без MOEX загрузите экспортированный ZIP через **Данные → Снимки ZIP**. Сохранённые рыночные кривые доступны из **Сценариев** и **Источников расчёта**. Новый учебный портфель можно построить на явно отмеченных учебных кривых. Установка зависимостей и первая сборка образа требуют доступа к реестрам.

- **Спектр локально.** Команды `start.command`, `start.bat` и `start.ps1` автоматически собирают интерфейс кривых при первом запуске. После обновления проекта перезапустите локальный сервер. [Запуск под macOS, Linux и Windows](factor-analysis/README.md#запуск)
- **Модуль кривых.** Самостоятельный Compose и React на 5173. [Инструкция команды 2](curves-module/README.md)
- **Калькулятор.** Операции по одиночному JSON, нормализованным и исходным CSV доступны из CLI. [Инструкция команды 1](calculator/README.md)

DeepSeek подключается через `DEEPSEEK_API_KEY`, `SPECTRUM_LLM_PROVIDER=deepseek` и отдельное разрешение внешних вызовов. Для Compose задайте переменные в окружении. При локальном запуске подходит исключённый из Git файл `factor-analysis/.env.local`. По умолчанию объяснения строятся по проверенным фактам. [Подключение DeepSeek и локальной модели](factor-analysis/README.md#объяснения-и-deepseek)

### Ограничения

Для портфельных оценок применяются готовые стандартные рыночные сценарии P/K/D = 4/5/3. Пользовательские перерасчёты сохраняются в истории кривых и доступны для исследования. Согласованный контракт для их использования в оценке ещё требуется. Договорные проценты, стрессовый ΔPV и итоговый Economic Capital описывают разные величины. Банковская валидация требует обезличенной многопериодной истории и согласованных определений EC и NII.

## Запуск калькулятора и кривых через Docker

Нужны Docker Desktop и Docker Compose с поддержкой `include` (2.20+).
Из корня репозитория:

```sh
make up
```

Команда создаст `curves-module/.env` из примера, только если файла ещё нет,
соберёт калькулятор и запустит PostgreSQL, миграции, API, независимый worker,
stress-service и интерфейс кривых. Go base-curve собирается в образ backend.
Порты по умолчанию: интерфейс http://127.0.0.1:5173, API http://127.0.0.1:8000.
При конфликтах измените `API_PORT` и `FRONTEND_PORT` в `curves-module/.env`.
Адреса внутри сети остаются `api:8000`, `stress:8081`, `postgres:5432`.

Проект Compose называется `economic-capital`. Его том `economic-capital_pg_data`
отдельный: существующая локальная рыночная БД `irrbb_moex` в другом стенде не подключается
и не меняется. Миграции автоматически выполняются только в БД из выбранного профиля.
Перед подключением существующей общей БД согласуйте её назначение и сделайте резервную копию.
Локальные примеры паролей из `.env.example` предназначены для разработки.

## Совместный расчёт

```sh
make calculate ARGS='examples/manual/simple-fixed-curves.json --manual --format csv --output-dir out/integration --cfcore /usr/local/bin/cfcore --curve-scenario all'
```

Пример использует отчётную дату 31.07.2026. Чтобы выбрать другую дату,
измените `reporting_date` в собственном JSON сделки и её договорные даты.
Для банковского CSV команда аналогична, без `--manual`.
Набор должен содержать одну отчётную дату и RUB. При нескольких датах разбейте файл
на отдельные запуски. Сценарии: `base`, `parallel_up`, `parallel_down`, `steepener`,
`flattener`, `short_rate_up`, `short_rate_down`, либо `all`. По умолчанию `base`.

В `calculator/out/integration` появятся:

- `curves/standard-result.json`: исходный ответ API без изменения чисел;
- `curves/curve-points.csv`: все семь кривых, независимо от выбранного сценария;
- `core/cashflows.csv` и прежние отчёты ядра;
- `core/discounted_cashflows.csv`: платёж, выбранный бакет, ставка, исходный DF и PV;
- `core/discounted_deal_summary.csv`: сумма PV по сделке и сценарию;
- `core/run_manifest.json`: дата/runId, сценарий, SHA-256 ответа и правило сопоставления;
- `integration-status.json`: `preparing/calculating/ready/failed` для текущей попытки.

При повторном использовании папки ориентируйтесь на `integration-status.json`:
ошибочная новая попытка не объявляет старые файлы новым готовым результатом.
PV активов положительна, обязательств отрицательна. Сценарии меняют DF,
но не подменяют договорные ставки или историю ключевой ставки калькулятора.
Ставки сделок по прежнему контракту калькулятора заданы долями; `ratePercent`
кривых уже задан в процентах. DF безразмерен и повторно не рассчитывается.

Этот пример запускается через CLI калькулятора. Портфельный расчёт из браузера
доступен в [«Спектре»](factor-analysis/README.md).

## Выбор DF и состояния API

Правило `calendar-bucket-v1` принято как рабочее решение по запросу пользователя.
Оно описано в [контракте интеграции](integration/CONTRACT.md).
Это бакетная оценка PV, а не вычисление новой кривой на точную дату каждого платежа.
Старые 19 бакетов C++ не меняются: дисконтирование использует даты отдельных платежей
и 23 интервала сетки кривых. Нет округления к ближайшему тенору, пересчёта DF
или автоматического продления сетки за 50 лет.

Сначала читается `GET /api/v1/curve-runs/standard-result?reportDate=...`.
Если готового результата нет, выполняется один идемпотентный POST подготовки даты,
затем опрашиваются подготовка и запуск до готовности. `--curves-wait` задаёт конечное
время ожидания (по умолчанию 120 секунд, дополнительно ограничены отдельные HTTP-запросы).
Неуверенный ответ POST восстанавливается чтением состояния, без повторного POST.
Завершённые результаты не опрашиваются. Закрытие клиента не отменяет worker.
Отсутствие публикации, ошибка источника, некорректный снимок и ошибка расчёта
завершают CLI с ненулевым кодом, без подстановки другой даты или нулей.

Полугодовая история исходного стенда не переносится через Git. На новом общем
стенде даты загружаются по запросу. Для предварительного заполнения своей согласованной
БД используйте штатный backfill, сначала `--report-only`. Например, для 21.11.2026:

```sh
docker compose exec api python -m web.processes.backfill --from 2026-05-21 --to 2026-11-21 --report-only
docker compose exec api python -m web.processes.backfill --from 2026-05-21 --to 2026-11-21
```

## Проверки и остановка

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e './calculator/cf-normalizer[dev]'
make check
make check-factor-analysis
make build-spectrum-ui
make logs
make spectrum-down
```

`make spectrum-down` сохраняет данные. Для самостоятельного стека из `make up` используйте `make down`.
Python-проверки кривых используют отдельную тестовую PostgreSQL с маркером `stage2`.
Общий CI сохраняет прежние проверки и дополнительно запускает C++/Python калькулятора.
