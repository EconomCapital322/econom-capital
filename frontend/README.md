# Frontend — модуль кривых IRRBB

React + TypeScript + Vite, Bootstrap, TanStack Query. Geologica подключена локально. Существующее оформление главной, таблицы, графика и модального окна сохранено.

## Запуск

Из `frontend`:

```sh
npm ci
cp -n .env.example .env.local
npm run dev
```

По умолчанию включён **реальный API**. Ошибка сервера не подменяется демонстрационными данными.

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=
```

Пустой URL означает тот же origin: `/api/v1/...`. В режиме разработки Vite проксирует `/api` на `http://127.0.0.1:8000`. В production нужен reverse proxy `/api` к FastAPI либо явно заданный `VITE_API_BASE_URL`, например `https://backend.example.org`. Указывать нужно origin/базовый путь **без** `/api/v1` в конце. Секреты в VITE_* помещать нельзя: они доступны браузеру.

Если запросы идут к отдельному origin, настрой `APP__CORS_ORIGINS` в backend на точный origin фронтенда. При локальном Vite proxy CORS для браузера не требуется.

### Backend

Проверенная серверная версия: `origin/backend-develop`, коммит `5cb62cbcc0479c4ab08c81b7c2ee040cddafbc62`. В текущий checkout фронтенда она не объединена. Команды ниже выполняются в отдельной копии этой серверной версии. Из её `backend`:

```sh
uv sync --frozen --group dev
cp -n .env.example .env
# Указать DATABASE__DSN для подготовленной PostgreSQL.
uv run alembic upgrade head
uv run uvicorn web.app:create_app --factory --host 127.0.0.1 --port 8000
```

Сначала собери реальную базовую кривую из корня репозитория:

```sh
(cd base && go build -o bin/base-curve ./cmd/base-curve)
export PATH="$(pwd)/base/bin:$PATH"
```

Затем вернись в `backend` для запуска API/worker. Нужны заполненные исходные ставки, согласованный `CALCULATION__SPEC_FILE` и отдельный Calculation Worker с настроенными реальными функциями и WORKER_*:

```sh
uv run python -m web.processes.calculation_worker
```

HTTP-процесс сам не запускает Worker/Loader и не выполняет миграции. Для временной локальной проверки PostgreSQL можно поднять `docker compose -f compose.test.yaml up -d --wait`, узнать порт через `docker compose -f compose.test.yaml port postgres-test 5432` и использовать реквизиты тестового контейнера из backend README. Его tmpfs не является постоянным хранилищем.

В версии `5cb62cb` подключён настоящий HTTP-мост к Go stress-service. В отдельном терминале из `stress` серверной копии:

```sh
go run ./cmd/stress-service
```

Для Python worker нужны переменные из `.env.example` этой версии:

```dotenv
INTEGRATIONS__BASE_FUNCTION=web.calculations.base_curve:build_base_curve
INTEGRATIONS__STRESS_HTTP_URL=http://127.0.0.1:8081/internal/v1/stress-curves
INTEGRATIONS__STRESS_HTTP_VERSION=<точное значение stress_version из спецификации>
INTEGRATIONS__STRESS_HTTP_TIMEOUT_SECONDS=10
INTEGRATIONS__STRESS_HTTP_MAX_RESPONSE_BYTES=8388608
CALCULATION__SPEC_FILE=<абсолютный путь к согласованной спецификации>
```

`STRESS_HTTP_URL` и `STRESS_FUNCTION` взаимоисключающие. Также обязательны `WORKER__POLL_SECONDS`, `WORKER__LEASE_SECONDS`, `WORKER__HEARTBEAT_SECONDS` и `WORKER__STAGE_TIMEOUT_SECONDS`: lease должен превышать три heartbeat-интервала. Значения этих таймаутов выбирает владелец серверной конфигурации. Не запускай worker до настройки.

В серверной версии есть `backend/examples/demo-calculation-spec.json` и команда `python -m web.processes.demo_history` для явно синтетического стенда. Эта команда разрешена только для отдельной БД с меткой `irrbb.demo_instance=backend-final`; производственная сетка и версии из неё не следуют. Для живого MOEX используйте `INTEGRATIONS__FETCH_FUNCTION=web.integrations.moex:fetch_rates` и отдельную рыночную БД; настройка — в `backend/MOEX.md`. Детали — [API_INTEGRATION.md](API_INTEGRATION.md).

### Демонстрационный режим

Явно укажи в `.env.local` и перезапусти Vite:

```dotenv
VITE_API_MODE=demo
```

Тогда используются локальные значения проверенного Excel за 31.07.2026, локальная математика. Панель демонстрации состояний удалена из интерфейса. Бэкенд, MOEX и БД не вызываются. В API-режиме этот инструмент отсутствует.

## Реализованный сценарий

- Выбор даты идемпотентно запрашивает подготовку: сервер использует сохранённые ставки либо загружает отсутствующие из MOEX и создаёт стандартный расчёт. Дата хранится в URL (`?reportDate=YYYY-MM-DD`) и восстанавливается после перезагрузки.
- При отсутствии запуска фронт проверяет появление данных/задания раз в 5 секунд, максимум 24 успешных ответа. Повторное открытие страницы перезапускает ожидание; отдельной кнопки проверки нет. Сетевые GET временно повторяются до двух раз; POST автоматически не повторяется.
- Queued/running автоматически опрашиваются каждые 1,5 секунды до ready/failed. Получается только полный готовый результат; ошибки и отсутствие данных различаются.
- Редактирование P/K/D сохраняет черновик без расчёта. Ручной запуск создаёт новое задание; перерасчёт использует снимок и базу родителя.
- Явное обновление открывает последний серверный запуск; собственное queued/running-задание остаётся выбранным до завершения. При 404 выбранного запуска адаптер один раз перечитывает историю и восстанавливает другой доступный результат. Сетевые ошибки не подменяются другим расчётом.
- Повторные клики и устаревшие ответы другой даты защищены. Отмена чтения/закрытие страницы не отменяет серверное задание. Список восстанавливает последний запуск при открытии.
- Все семь кривых показаны в таблице; линии графика выбираются независимо, масштаб Y фиксирован по результату. Шеврон скрывает выбор и увеличивает график. Вкладки не запускают расчёт.
- CSV включает все семь кривых независимо от выбора, исходные параметры результата, происхождение данных и способ запуска, BOM и корректное экранирование. Ручки серверного экспорта в текущем API нет.
- На ноутбуке страница занимает высоту окна, блок результатов занимает оставшуюся высоту окна, отступы между основными блоками — 24 px, прокрутка строк под заголовками, постоянное положение скачивания и плавная плашка вкладок сохранены. Ошибка расчёта — в центре белого блока. В модальном окне ошибки не сдвигают элементы; работают Escape, удержание и возврат фокуса.

### Ограничения контракта

Фронтенд и текущая локальная серверная связка поддерживают конечные `0 < P/K/D ≤ 50`, включая `0.001`. Значения не округляются и не обрезаются; серверные ошибки обрабатываются отдельно. Проверка старой версии с пределом 25 ниже сохранена как историческая запись.

Гибридная загрузка требует миграции 0007, `AUTOMATION__ENABLED=true`, рыночной спецификации и работающего worker. Без этой настройки API возвращает ошибку готовности, а не фиктивный результат. Команды и переменные — в `backend/MOEX.md`. Согласование производственной сетки и версии расчётных алгоритмов остаётся отдельной задачей.

## Проверка

```sh
npm run typecheck
npm run lint
npm run build
```

Автотестов во фронтенде пока нет. Основной сценарий проверяется вручную:

1. Выбрать дату с данными и открыть сохранённый результат.
2. Изменить P/K/D: до нажатия кнопки новый расчёт не запускается.
3. Запустить перерасчёт, дождаться завершения и проверить параметры результата.
4. Переключить график/таблицу, выбрать линии и свернуть выбор кривых.
5. Скачать CSV и проверить полный комплект из семи кривых.
6. Проверить отсутствие данных, ошибку сервера и повторную попытку.
7. Сменить дату во время ожидания: старый результат не появляется под новой датой.
8. Повторно открыть страницу после запуска: принятое сервером задание продолжает выполняться.
9. Проверить границы P/K/D, дробные значения, отмену, Escape и возврат фокуса в окне параметров.

Информация об интеграции и оставшихся препятствиях — [API_INTEGRATION.md](API_INTEGRATION.md).

## Гибридная подготовка даты

После миграции backend до 0007 и включения AUTOMATION__ENABLED выбор даты выполняет идемпотентный POST /api/v1/curve-preparations. Существующие ставки используются из БД; отсутствующие ставятся в долговечную очередь. Worker получает MOEX и создаёт стандартный расчёт. Чтение GET не создаёт задания.

GET /api/v1/curve-preparations?reportDate=YYYY-MM-DD возвращает отдельное состояние загрузки: idle, queued, running, ready, no_data или failed, а также runId и errorCode (nullable). ready здесь означает завершение подготовки исходных данных и постановку расчёта; готовность семи кривых проверяется по обычному curve-run.

Повторы POST при StrictMode/новой вкладке безопасны на сервере. В одной вкладке одновременно используется один запрос подготовки на дату. Потеря ответа POST восстанавливается чтением состояния, без автоматической повторной отправки. После ошибки доступен явный повтор загрузки. Закрытие страницы не отменяет задание. Для текущей московской даты no_data проверяется раз в минуту, чтобы заметить вечернее появление ставок.

Расписание находится в объединённом backend worker, а не во фронте. Для локального профиля задано 19:15 Europe/Moscow и проверка пропущенных публикаций за 7 дней. Рабочее время публикации согласуется отдельно; компьютер и worker должны оставаться включёнными.

## История запусков за дату

Кнопка «История» находится справа от уменьшенного блока настроек. Панель показывает до 10 последних запусков выбранной даты: время МСК, параметры, происхождение запуска и статус. Список читается через существующий GET /api/v1/curve-runs?reportDate=..., при открытии обновляется. Это не общая история за диапазон дат; серверной пагинации нет.

Выбор запуска читает его состояние и готовый результат, не вызывает подготовку даты или POST. Явный выбор сохраняется между вкладками и при обновлении списка. Пара reportDate/runId в URL восстанавливает выбранный результат после перезагрузки. При смене даты выбор очищается. Собственный принятый перерасчёт становится выбранным; его родитель — выбранный запуск с сохранённой базой. Редактируемые P/K/D не заменяются параметрами просматриваемой истории. График, таблица и полный CSV используют один сохранённый результат.

Проверено вручную 31.10.2026 с действующим локальным API, worker и Go-сервисом на реальных ставках MOEX: список за 30.10, открытие стандартного результата и результата с 0.001 без POST, восстановление URL, сохранение редактируемых параметров, перерасчёт на выбранном родителе, ожидание и готовность нового запуска, смена даты, график/таблица и неизменное положение выгрузки. CSV содержит 77 строк для семи кривых, BOM и сохранённые параметры. Проверены пустая история за 31.10, неверный UUID, недоступный UUID с восстановлением доступного результата, Escape и возврат фокуса, ширины 1440/1024/390/320 и длинные дробные параметры. Ошибка чтения списка и повтор проверены намеренным обрывом одного GET в браузере; остальные проверки выполнялись с реальным API.

В доступной истории было менее 10 запусков; список более 10 записей и выбор реально failed/queued-запуска из панели отдельно не воспроизводились. Искусственные записи в БД и фронтенд-тестовые зависимости не добавлялись.
