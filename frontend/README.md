# Frontend — модуль кривых IRRBB

React + TypeScript + Vite, Bootstrap, TanStack Query. Geologica подключена локально. Существующее оформление главной, таблицы, графика и модального окна сохранено.

## Запуск

Из `frontend`:

```sh
npm ci
cp -n .env.example .env.local
npm run dev
```

По умолчанию включён **реальный API**. Ошибка сервера не подменяется демонстрационными данными.

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=
```

Пустой URL означает тот же origin: `/api/v1/...`. В режиме разработки Vite проксирует `/api` на `http://127.0.0.1:8000`. В production нужен reverse proxy `/api` к FastAPI либо явно заданный `VITE_API_BASE_URL`, например `https://backend.example.org`. Указывать нужно origin/базовый путь **без** `/api/v1` в конце. Секреты в VITE_* помещать нельзя: они доступны браузеру.

Если запросы идут к отдельному origin, настрой `APP__CORS_ORIGINS` в backend на точный origin фронтенда. При локальном Vite proxy CORS для браузера не требуется.

### Backend

Проверенная серверная версия: `origin/backend-develop`, коммит `5cb62cbcc0479c4ab08c81b7c2ee040cddafbc62`. В текущий checkout фронтенда она не объединена. Команды ниже выполняются в отдельной копии этой серверной версии. Из её `backend`:

```sh
uv sync --frozen --group dev
cp -n .env.example .env
# Указать DATABASE__DSN для подготовленной PostgreSQL.
uv run alembic upgrade head
uv run uvicorn web.app:create_app --factory --host 127.0.0.1 --port 8000
```

Сначала собери реальную базовую кривую из корня репозитория:

```sh
(cd base && go build -o bin/base-curve ./cmd/base-curve)
export PATH="$(pwd)/base/bin:$PATH"
```

Затем вернись в `backend` для запуска API/worker. Нужны заполненные исходные ставки, согласованный `CALCULATION__SPEC_FILE` и отдельный Calculation Worker с настроенными реальными функциями и WORKER_*:

```sh
uv run python -m web.processes.calculation_worker
```

HTTP-процесс сам не запускает Worker/Loader и не выполняет миграции. Для временной локальной проверки PostgreSQL можно поднять `docker compose -f compose.test.yaml up -d --wait`, узнать порт через `docker compose -f compose.test.yaml port postgres-test 5432` и использовать реквизиты тестового контейнера из backend README. Его tmpfs не является постоянным хранилищем.

В версии `5cb62cb` подключён настоящий HTTP-мост к Go stress-service. В отдельном терминале из `stress` серверной копии:

```sh
go run ./cmd/stress-service
```

Для Python worker нужны переменные из `.env.example` этой версии:

```dotenv
INTEGRATIONS__BASE_FUNCTION=web.calculations.base_curve:build_base_curve
INTEGRATIONS__STRESS_HTTP_URL=http://127.0.0.1:8081/internal/v1/stress-curves
INTEGRATIONS__STRESS_HTTP_VERSION=<точное значение stress_version из спецификации>
INTEGRATIONS__STRESS_HTTP_TIMEOUT_SECONDS=10
INTEGRATIONS__STRESS_HTTP_MAX_RESPONSE_BYTES=8388608
CALCULATION__SPEC_FILE=<абсолютный путь к согласованной спецификации>
```

`STRESS_HTTP_URL` и `STRESS_FUNCTION` взаимоисключающие. Также обязательны `WORKER__POLL_SECONDS`, `WORKER__LEASE_SECONDS`, `WORKER__HEARTBEAT_SECONDS` и `WORKER__STAGE_TIMEOUT_SECONDS`: lease должен превышать три heartbeat-интервала. Значения этих таймаутов выбирает владелец серверной конфигурации. Не запускай worker до настройки.

В серверной версии есть `backend/examples/demo-calculation-spec.json` и команда `python -m web.processes.demo_history` для явно синтетического стенда. Эта команда разрешена только для отдельной БД с меткой `irrbb.demo_instance=backend-final`; производственная сетка и версии из неё не следуют. Полная загрузка из живого MOEX по-прежнему требует настоящего `INTEGRATIONS__FETCH_FUNCTION`. Детали — [API_INTEGRATION.md](API_INTEGRATION.md).

### Демонстрационный режим

Явно укажи в `.env.local` и перезапусти Vite:

```dotenv
VITE_API_MODE=demo
```

Тогда используются локальные значения проверенного Excel за 31.07.2026, локальная математика и явно обозначенный инструмент демонстрации ошибки/отсутствия данных. Бэкенд, MOEX и БД не вызываются. В API-режиме этот инструмент отсутствует.

## Реализованный сценарий

- Выбор даты получает исходные ставки и последний сохранённый запуск. Дата хранится в URL (`?reportDate=YYYY-MM-DD`), поэтому сохраняется после перезагрузки. Просмотр не создаёт POST.
- При отсутствии запуска фронт проверяет появление данных/задания раз в 5 секунд, максимум 24 успешных ответа. Кнопка проверки перезапускает ожидание. Сетевые GET временно повторяются до двух раз; POST автоматически не повторяется.
- Выбор даты только читает данные. Версия backend `5cb62cb` требует явного пользовательского POST: при ставках без готового запуска фронт предлагает кнопку расчёта и не обещает автоматическое завершение.
- Queued/running автоматически опрашиваются каждые 1,5 секунды до ready/failed. Получается только полный готовый результат; ошибки и отсутствие данных различаются.
- Редактирование P/K/D сохраняет черновик без расчёта. Ручной запуск создаёт новое задание; перерасчёт использует снимок и базу родителя.
- Явное обновление открывает последний серверный запуск; собственное queued/running-задание остаётся выбранным до завершения. При 404 выбранного запуска адаптер один раз перечитывает историю и восстанавливает другой доступный результат. Сетевые ошибки не подменяются другим расчётом.
- Повторные клики и устаревшие ответы другой даты защищены. Отмена чтения/закрытие страницы не отменяет серверное задание. Список восстанавливает последний запуск при открытии.
- Все семь кривых показаны в таблице; линии графика выбираются независимо, масштаб Y фиксирован по результату. Шеврон скрывает выбор и увеличивает график. Вкладки не запускают расчёт.
- CSV включает все семь кривых независимо от выбора, исходные параметры результата, происхождение данных и способ запуска, BOM и корректное экранирование. Ручки серверного экспорта в текущем API нет.
- На ноутбуке страница занимает высоту окна, блок результатов подстраивается под свободное место (до 499 px), отступы между основными блоками — 24 px, прокрутка строк под заголовками, постоянное положение скачивания и плавная плашка вкладок сохранены. Ошибка расчёта — в центре белого блока. В модальном окне ошибки не сдвигают элементы; работают Escape, удержание и возврат фокуса.

### Ограничения контракта

Фронтенд поддерживает конечные `0 < P/K/D ≤ 50`, включая дроби. Текущие Python-модели, CHECK PostgreSQL и Go ограничивают параметры значением 25: до их отдельного обновления запросы с параметрами выше 25 будут отклоняться сервером. Поддержка диапазона до 50 по всей цепочке пока не завершена. Значения не обрезаются.

Loader сохраняет ставки, но версия `5cb62cb` намеренно требует отдельного POST для запуска. Это расходится с продуктовым требованием автоматического стандартного результата и должно быть решено серверной командой. Фронт не делает скрытых POST и не подменяет результат локальным расчётом. Базовый и стрессовый Go-адаптеры в этой серверной версии есть; остаются настройка, настоящий MOEX-fetch и согласованная производственная спецификация. Список необходимых серверных изменений — в [API_INTEGRATION.md](API_INTEGRATION.md#что-нужно-изменить-на-бэкенде).

## Проверка

```sh
npm run typecheck
npm run lint
npm run build
```

Автотестов во фронтенде пока нет. Основной сценарий проверяется вручную:

1. Выбрать дату с данными и открыть сохранённый результат.
2. Изменить P/K/D: до нажатия кнопки новый расчёт не запускается.
3. Запустить перерасчёт, дождаться завершения и проверить параметры результата.
4. Переключить график/таблицу, выбрать линии и свернуть выбор кривых.
5. Скачать CSV и проверить полный комплект из семи кривых.
6. Проверить отсутствие данных, ошибку сервера и повторную попытку.
7. Сменить дату во время ожидания: старый результат не появляется под новой датой.
8. Повторно открыть страницу после запуска: принятое сервером задание продолжает выполняться.
9. Проверить границы P/K/D, дробные значения, отмену, Escape и возврат фокуса в окне параметров.

Информация об интеграции и оставшихся препятствиях — [API_INTEGRATION.md](API_INTEGRATION.md).

Фронт проверен в браузере с отдельной копией backend `5cb62cb`, изолированной PostgreSQL, независимым worker, настоящим Go `base-curve` и штатным Python HTTP-адаптером к настоящему Go stress-service. Серверные исходники не изменялись. История и спецификация стенда были явно синтетическими, живой MOEX не вызывался.

Проверены сохранённый результат, дата со ставками без запусков, ручной первый расчёт, P=0.001 и K=25, отказы сервера на 25.001 и 50, клиентский запрет 0 и 50.001, отмена через Escape и возврат фокуса, смена даты после POST, восстановление даты/расчёта после перезагрузки, обновление до нового внешнего запуска, ошибка отключённого Go-сервиса и повтор после восстановления. После подмены принятого ответа POST (202) на ошибку шлюза (502) интерфейс восстановил запуск без второго POST; один временный 503 на GET был повторён. Отсутствующий выбранный UUID дополнительно проверен самим HTTP-адаптером через настоящий API: 404 восстанавливает актуальный запуск.

График, выбор линий, таблица и скачанный CSV проверены: 35 строк для 5 примерных сроков и всех 7 кривых, BOM, сохранённые P/K/D, «Синтетические» и «Ручной» в каждой строке. Это проверка реальной вычислительной цепочки на синтетических данных, а не готовности живой загрузки MOEX. Физический обрыв сети и недоступность PostgreSQL отдельно не воспроизводились. TypeScript, ESLint и production-сборка прошли.
