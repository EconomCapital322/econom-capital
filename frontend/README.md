# Frontend — модуль кривых IRRBB

React + TypeScript + Vite, Bootstrap, TanStack Query. Geologica подключена локально. Существующее оформление главной, таблицы, графика и модального окна сохранено.

## Запуск

Из `frontend`:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

По умолчанию включён **реальный API**. Ошибка сервера не подменяется демонстрационными данными.

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=
```

Пустой URL означает тот же origin: `/api/v1/...`. В режиме разработки Vite проксирует `/api` на `http://127.0.0.1:8000`. В production нужен reverse proxy `/api` к FastAPI либо явно заданный `VITE_API_BASE_URL`, например `https://backend.example.org`. Указывать нужно origin/базовый путь **без** `/api/v1` в конце. Секреты в VITE_* помещать нельзя: они доступны браузеру.

Если запросы идут к отдельному origin, настрой `APP__CORS_ORIGINS` в backend на точный origin фронтенда. При локальном Vite proxy CORS для браузера не требуется.

### Backend

Полная инструкция — [backend/README.md](../backend/README.md). Из `backend`:

```sh
uv sync --frozen --group dev
cp .env.example .env
# Указать DATABASE__DSN для подготовленной PostgreSQL.
uv run alembic upgrade head
uv run uvicorn web.app:create_app --factory --host 127.0.0.1 --port 8000
```

Нужны заполненные исходные ставки, согласованный `CALCULATION__SPEC_FILE` и отдельный Calculation Worker с настроенными реальными функциями и WORKER_*:

```sh
uv run python -m web.processes.calculation_worker
```

HTTP-процесс сам не запускает Worker/Loader и не выполняет миграции. Для временной локальной проверки PostgreSQL можно поднять `docker compose -f compose.test.yaml up -d --wait`, узнать порт через `docker compose -f compose.test.yaml port postgres-test 5432` и использовать реквизиты тестового контейнера из backend README. Его tmpfs не является постоянным хранилищем.

**Сейчас реальная MOEX/математическая цепочка не завершена в backend.** Не заполняй настройки вымышленной сеткой или версиями ради статуса ready. Детали расхождений — [API_INTEGRATION.md](API_INTEGRATION.md).

### Демонстрационный режим

Явно укажи в `.env.local` и перезапусти Vite:

```dotenv
VITE_API_MODE=demo
```

Тогда используются локальные значения проверенного Excel за 31.07.2026, локальная математика и явно обозначенный инструмент демонстрации ошибки/отсутствия данных. Бэкенд, MOEX и БД не вызываются. В API-режиме этот инструмент отсутствует.

## Реализованный сценарий

- Выбор даты получает исходные ставки и последний сохранённый запуск. Просмотр не создаёт POST.
- Queued/running автоматически опрашиваются каждые 1,5 секунды до ready/failed. Получается только полный готовый результат; ошибки и отсутствие данных различаются.
- Редактирование P/K/D сохраняет черновик без расчёта. Ручной запуск создаёт новое задание; перерасчёт использует снимок и базу родителя.
- Повторные клики и устаревшие ответы другой даты защищены. Отмена чтения/закрытие страницы не отменяет серверное задание. Список восстанавливает последний запуск при открытии.
- Все семь кривых показаны в таблице; линии графика выбираются независимо, масштаб Y фиксирован по результату. Шеврон скрывает выбор и увеличивает график. Вкладки не запускают расчёт.
- CSV включает все семь кривых независимо от выбора, исходные параметры результата, BOM и корректное экранирование. Ручки серверного экспорта в текущем API нет.
- Высота результатов 499 px, отступы 24 px, прокрутка строк под заголовками, постоянное положение скачивания и плавная плашка вкладок сохранены. Ошибка расчёта — в центре белого блока. В модальном окне ошибки не сдвигают элементы; работают Escape, удержание и возврат фокуса.

### Ограничения контракта

Фронтенд принимает конечные `0 < P/K/D ≤ 50`, дроби поддерживаются. **FastAPI и Go пока ограничены 25**: большее значение получает понятную ошибку сервера, не обрезается и не рассчитывается локально.

MOEX Loader сейчас не создаёт расчёты автоматически. При ставках без запусков фронт показывает отсутствие готового расчёта и предлагает явный запуск. Требуемый автоматический старт после загрузки должен быть завершён в backend. Реальные fetch/base/stress функции и расчётная спецификация также требуют подключения.

## Проверка

```sh
npm run typecheck
npm run lint
npm run build
```

Автотестов во фронтенде пока нет. Основной сценарий проверяется вручную:

1. Выбрать дату с данными и открыть сохранённый результат.
2. Изменить P/K/D: до нажатия кнопки новый расчёт не запускается.
3. Запустить перерасчёт, дождаться завершения и проверить параметры результата.
4. Переключить график/таблицу, выбрать линии и свернуть выбор кривых.
5. Скачать CSV и проверить полный комплект из семи кривых.
6. Проверить отсутствие данных, ошибку сервера и повторную попытку.
7. Сменить дату во время ожидания: старый результат не появляется под новой датой.
8. Повторно открыть страницу после запуска: принятое сервером задание продолжает выполняться.
9. Проверить границы P/K/D, дробные значения, отмену, Escape и возврат фокуса в окне параметров.

Информация об интеграции и оставшихся препятствиях — [API_INTEGRATION.md](API_INTEGRATION.md).
