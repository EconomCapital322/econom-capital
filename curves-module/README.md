# curves-module

Модуль кривых IRRBB проекта Economic Capital. Локальный запуск объединяет PostgreSQL, миграции, FastAPI, worker, Go-сервис стрессовых кривых и Vite. Go-программа базовой кривой вызывается worker как подпроцесс.

## Локальный запуск

Нужны Docker с Compose и `make`. Из корня репозитория:

```sh
cp .env.example .env
make up
```

`.env` обязателен: перед первым запуском проверьте в нём имя БД, пароль и адреса/порты. Файл игнорируется Git. Значения в `.env.example` предназначены только для локальной разработки. `make up` собирает образы, ждёт PostgreSQL и миграции, затем запускает остальные компоненты.

- Интерфейс: <http://127.0.0.1:5173/>.
- API: <http://127.0.0.1:8000/docs>.
- `API_BIND_ADDRESS`, `API_PORT`, `FRONTEND_BIND_ADDRESS` и `FRONTEND_PORT` в `.env` меняют опубликованные адреса и порты. Внутри Compose API слушает `8000`, фронтенд — `5173`.
- Vite отправляет `/api` на `API_PROXY_TARGET`; штатное значение — `http://api:8000`. `VITE_API_MODE=api` использует настоящий API. Секреты нельзя помещать в `VITE_*`: браузер видит эти значения.

Обычный профиль использует MOEX. При выборе даты worker запрашивает отсутствующие ставки и создаёт расчёт; ежедневная проверка настроена на `19:15 Europe/Moscow`. Пустой ответ MOEX означает отсутствие опубликованных данных, а не ошибку запуска контейнеров. Локальная спецификация — `backend/examples/moex-excel-grid-spec.json`; её метка стрессового алгоритма `demo-only-go-stress` не является утверждённой производственной версией. Подробности источника и расчётной сетки — в [backend/MOEX.md](backend/MOEX.md).

## Управление

```sh
make logs                 # следить за логами всех сервисов
make down                 # остановить стек, сохранив PostgreSQL
make up                   # запустить снова с сохранёнными данными
make restart-worker       # перезапустить worker после правки Python-кода
make rebuild              # пересобрать и перезапустить stress и worker после правок Go
make check                # все проверки на отдельной временной тестовой БД
```

API и фронтенд автоматически подхватывают изменения исходников. Worker и Go-сервис требуют команд перезапуска выше. `make check` запускает pytest, Ruff, mypy, Go race-тесты и vet в обоих модулях, затем TypeScript, ESLint и сборку фронтенда. Тестовая БД отделена от постоянного рыночного тома и останавливается после проверок.

## CI и будущая выкладка

GitHub Actions запускает проверки Python, Go и фронтенда отдельными заданиями для каждого pull request в `main` или `curves-module` и каждого push в эти ветки. Сводное задание `Project CI / check` проходит после успеха всех трёх. Для pull request в эти же ветки задание `Go CI / lint` запускает golangci-lint и проверяет форматирование Go. В `Project CI` временный `.env` создаётся из `.env.example` внутри каталога `curves-module/`. Для локального запуска проверок выполните `make check` из этого каталога.

Автоматическая выкладка пока не включена: тестовый стенд не предоставлен. Для её настройки нужны адрес стенда, способ доступа, конфигурация запуска и секретов, проверка состояния приложения после релиза и процедура отката. Выкладку следует запускать только из `main` после успешного CI и проверить на реальном стенде до закрытия задачи CI/CD. Текущий Compose-профиль описывает локальную разработку; его настройки API и фронтенда включают перезагрузку и dev-сервер.

Для **удаления локальной БД** используйте только явную команду:

```sh
make reset-local-db CONFIRM=delete-local-data
```

Она удаляет тома Compose, включая историю расчётов и кэш зависимостей фронтенда. Обычный `make down` тома не удаляет.

Если `make up` не завершился успешно, проверьте `docker compose ps` и `make logs`. Частые причины: Docker не запущен, занят порт `8000` или `5173`, отсутствует `.env`, либо переменные в нём не согласованы. Не направляйте тесты или локальный профиль на пользовательскую PostgreSQL.
