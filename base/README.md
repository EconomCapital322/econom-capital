# Базовая кривая

Go-модуль построения базовой кривой согласно схеме архитектуры проекта.
`Build(points []RatePoint, spec Spec) (Curve, error)` возвращает сроки, бакеты,
рассчитанные ставки и признаки происхождения точек. `cmd/base-curve` предоставляет
ту же функцию через JSON stdin/stdout. Подключение к существующему Python Worker
описано в [backend/BASE_CURVE.md](../backend/BASE_CURVE.md).

## Интерполяция и экстраполяция

Исходные точки сортируются по числовому сроку. Нужны минимум две точки с разными
положительными сроками и конечными ставками. Повторные сроки отклоняются, даже если
ставки совпадают. Отрицательные и нулевые ставки допустимы. Вход не изменяется.

Для соседних исходных точек `(t₁, r₁)`, `(t₂, r₂)`:

```text
r(t) = r₁ + (r₂ − r₁) × (t − t₁) / (t₂ − t₁)
```

- Внутри диапазона используется пара, окружающая целевой срок.
- Слева продолжается прямая через первые две исходные точки.
- Справа продолжается прямая через последние две исходные точки.
- При точном совпадении срока возвращается исходная ставка без округления.

Результат содержит ровно заданную `spec.grid`. Метки и сроки копируются без
подмены. Метка — идентификатор, срок не извлекается из её текста. Сетка непустая,
сроки строго возрастают, метки уникальны. Обязательной производственной сетки нет.

Поддерживаются `base_version="linear-v1"` и `method="linear"`. Неизвестная версия,
метод или некорректный вход дают ошибку без частичной кривой. `day_count` и
`stress_version` — обязательные метаданные запуска. Функция получает готовые
годовые сроки и не преобразует календарные даты. Версия стрессов в расчёте базы
не участвует.

Сроки — годы, ставки — **проценты годовых**: `14.5` означает 14,5%, деления на 100
нет. Транспортные числа представлены десятичными строками. `math/big.Rat`
вычисляет формулу точно; только конечная рассчитанная ставка округляется до
**34 значащих десятичных цифр, половины к чётному (ROUND_HALF_EVEN)**. Промежуточного
float нет. Это численная политика `linear-v1`, для производственного применения
её следует утвердить вместе с сеткой/day count.

## Запуск

Требуется Go версии из `go.mod`. Из каталога `base`:

```sh
mkdir -p bin
go build -o bin/base-curve ./cmd/base-curve
./bin/base-curve <<'JSON'
{
  "points": [
    {"tenor_years": "1", "rate_percent": "2"},
    {"tenor_years": "3", "rate_percent": "6"}
  ],
  "spec": {
    "base_version": "linear-v1",
    "stress_version": "example-stress-v1",
    "method": "linear",
    "day_count": "ACT/365F",
    "grid": [{"bucket_label": "2y", "tenor_years": "2"}]
  }
}
JSON
```

Результат:

```json
{"curve_code":"base","points":[{"bucket_label":"2y","tenor_years":"2","rate_percent":"4","is_interpolated":true,"is_extrapolated":false}]}
```

Код выхода `0` — готовая кривая; `1` — ошибка расчёта/данных; `2` — некорректный
JSON, типы, неизвестные поля или несколько JSON-значений. Диагностика идёт в
stderr, при неверном входе stdout пуст.

## Формат для Славы / yyeart

Совместим с `BaseCurveRequest`, `BasePointRequest`, `CalculateRequest` в
`../stress/internal/httpapi/dto.go`. Потребитель —
`POST /internal/v1/stress-curves`. Готовая база помещается в поле `base`:

```json
{
  "base": {
    "curve_code": "base",
    "points": [
      {
        "bucket_label": "1y",
        "tenor_years": "1",
        "rate_percent": "3",
        "is_interpolated": true,
        "is_extrapolated": false
      }
    ]
  },
  "parameters": {"mode":"standard","p":"4","k":"5","d":"3"}
}
```

| Поле | Тип и смысл |
| --- | --- |
| `curve_code` | Строка `"base"` |
| `points` | Непустой массив с возрастающими сроками и уникальными метками |
| `bucket_label` | Непустая строка, идентификатор бакета |
| `tenor_years` | Десятичная строка, положительный срок в годах |
| `rate_percent` | Десятичная строка, ставка в процентах годовых |
| `is_interpolated` | Обязательный JSON boolean |
| `is_extrapolated` | Обязательный JSON boolean |
| `parameters.mode` | `standard` либо `custom` |
| `parameters.p/k/d` | Десятичные строки в п.п.; требуемый диапазон custom: (0, 50]; standard: 4/5/3 |

У исходного узла оба признака `false`; у интерполированного — `true/false`,
у экстраполированного — `false/true`. Комбинация `true/true` недопустима.
Стрессовый ответ содержит шесть кривых в `{"curves":[...]}`, с теми же метками
и сроками, без признаков происхождения.

Стресс-модуль пока использует float64. Сохранение Decimal в транспорте не означает
точную арифметику стрессов. Числа должны помещаться в конечный float64 без потери
ненулевого значения до нуля; допуск стрессового расчёта утверждается отдельно.
Публичное API backend сохраняет существующий camelCase-формат с JSON numbers.

Полный пример для передачи: [examples/stress-request.json](examples/stress-request.json).
Он соответствует [исходным точкам](examples/base-curve-input.json) и
[спецификации](examples/linear-calculation-spec.json). Это синтетические данные:

| Бакет | Срок, лет | Ставка, % годовых | Происхождение |
| --- | ---: | ---: | --- |
| 3m | 0.25 | 1.5 | Экстраполяция |
| 6m | 0.5 | 2 | Исходный узел |
| 1y | 1 | 3 | Интерполяция |
| 18m | 1.5 | 4 | Исходный узел |
| 2y | 2 | 3 | Интерполяция |
| 3y | 3 | 1 | Исходный узел |
| 4y | 4 | -1 | Экстраполяция |

Python-тест строит базу реальным Go-бинарником и сверяет JSON с примером. Go-тест
стресс-модуля передаёт тот же файл в действующий HTTP handler и проверяет все
шесть кривых и их сетку. Личное подтверждение yyeart не получено; описание
подготовлено для согласования на основании его уже реализованного DTO.

## Сверка и тесты

```sh
go test -race ./...
go vet ./...
```

[testdata/excel.json](testdata/excel.json) извлечён из предоставленного файла
`практика_Т1_спринт1 (3).xlsx`, лист `Лист1`. SHA256 записан в фикстуре.
Исходные сроки — B15:T15, исходные ставки — B4:T4, бакеты/теноры — B2:X3,
ожидаемые ставки — сохранённые B17:X17. Тест проверяет 19 исходных точек и все
23 результата, включая четыре экстраполированных срока 32.5–47.5 года.
Сохранённые значения Excel не пересчитывались. Сверка допускает абсолютную
разницу `1e-12` процентного пункта из-за float-значений Excel; это тестовый допуск,
а не утверждённая производственная погрешность.

Y:AC исключены: в них отсутствует полная сетка бакетов/теноров, а Y16 ссылается
на пустую Y3. Исходный Excel не изменён. Другие тесты покрывают неверные числа,
дубликаты, сетку, точность, округление, неизменяемость входа и CLI-ошибки.
