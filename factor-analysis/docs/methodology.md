# Методология «Спектра»

## Архитектура и источник чисел

```text
Генератор сделок / готовые снимки ZIP / таблица CSV
    → проверка дат, схемы, ID, валюты и источников
    → договорные платежи C++ и кривые команды 2 для финансового расчёта
    → наблюдения на отчётную дату
    → расчётный режим или ML-режим
    → отчёт с analysisId, источниками, проверками и ограничениями
    → браузер, экспорт и объяснение по проверенным фактам
```

Команда 1 строит расписания. Команда 2 выдаёт базовую кривую и шесть стрессов. «Спектр» повторно использует общий модуль `normalizer.discounting`. Для каждой даты хранятся вход калькулятора, платежи, сводки, исходный JSON, идентификатор расчёта и SHA-256 кривых. В генераторе договоры синтетические. Кривые могут быть рыночными, ранее сохранёнными или явно учебными. [Совместный контракт](../../integration/CONTRACT.md)

## Режим A. Расчётное разложение

`PV = CF × DF`, где CF учитывает знак стороны сделки. Для актива знак положительный, для обязательства отрицательный. Платёж относится к бакету, определённому относительно **его отчётной даты** по `calendar-bucket-v1`. Например, «до 1 месяца» — один и тот же интервал на двух датах, хотя его календарная граница различается. Сопоставление по относительному бакету позволяет применять веса второй даты к потокам первой и наоборот. Перенос оставшихся платежей между сроками входит в эффект потоков.

Для общих ID обозначим `Vij = Σ CFᵢ(b) × wⱼ(b)`. В NPV вес `w` — готовый `DF_base`. Для изменения ΔPV вес `w = DF_stress − DF_base`. Коэффициенты берутся из исходного JSON, ставки в отдельные DF не переводятся. В каждом сценарии сравниваются договорные потоки по согласованному контракту. Окончательный NII с переоценкой договорных ставок и фондированием требует другой методики.

```text
C_CF = [(V10 − V00) + (V11 − V01)] / 2
C_DF = [(V01 − V00) + (V11 − V10)] / 2
I    = V11 − V10 − V01 + V00
ΔPV  = вклад новых + вклад выбывших + C_CF + C_DF + расчётная невязка
```

Последняя строка относится к выбранной метрике и сравнению дат. Совместный эффект `I` уже учтён по половине в двух вкладах. Новые ID берутся по фактической оценке на конец, выбывшие — по фактической оценке на начало с обратным знаком. При наличии обоих снимков можно переключать все шесть стрессов без пересчёта C++.

По каждой сделке и каждому сценарию независимо сверяются исходные PV, сетка бакетов, стороны, соответствие ID и количество платежей. Суммирование — `Decimal` с 44 значащими цифрами. Сравнение с неокруглённой выгрузкой использует абсолютный допуск 0,000001 ₽ на сделку и на итог. Десятичные числа для аудита сохраняются в JSON. Статус **Сверено с калькулятором** означает согласованность входов и арифметики. Применимость финансовой методики проверяется отдельно.

### Пример вручную

100 ₽ платежа на начало с DF 0,80 дают 80 ₽. На конец платёж 120 ₽ и DF 0,90 дают 108 ₽. Для одних и тех же сделок `V00 = 80`, `V10 = 96`, `V01 = 90`, `V11 = 108`. Из 28 ₽ прироста 17 ₽ приходятся на потоки, 11 ₽ — на DF. Совместный эффект 2 ₽ уже распределён между этими значениями. Для отдельной новой сделки берётся её полная стоимость на конец.

Разбивка по сроку и типу платежа точная по той же формуле. Долг, ставки и схемы погашения зависимы между собой, поэтому их независимые расчётные вклады требуют допустимых контрфактических договоров. В текущем расчёте эти эффекты объединены в потоках. Для итогового экономического капитала нужна утверждённая формула. В интерфейсе можно посмотреть минимум стрессовой ΔPV и потоки за год.

## Режим B. Универсальное разложение по модели

Единица наблюдения — одна строка на пару «ID и дата». Метрика суммируется по наблюдениям. Общий описательный профиль содержит типы, число пропусков, уникальность, диапазон и выбросы по 1,5 межквартильного размаха. Решения о признаках, заполнении пропусков и кодировании принимаются по обучающей части. Константы, технические ID, поля с большим количеством пропусков, даты, признаки с более 30 категориями, признаки с именами будущих значений и почти точные аффинные копии цели отмечаются и исключаются. Статистический фильтр выявляет типовые утечки. Семантику колонки проверяет пользователь. Если изменчивых кандидатов больше 16, взаимная информация ранжирует их на воспроизводимой обучающей подвыборке до 2 048 строк. Пользователь может исключать поля явно.

Модель выбирается по средней MAE на расширяющихся временных фолдах, заканчивающихся до первой даты сравнения. Кандидаты — медиана, Ridge, Random Forest и Extra Trees. При разнице в пределах 1% от лучшей MAE выбирается более простая модель. При отсутствии фолдов применяется базовый случайный лес и показывается ограничение. Extra Trees даёт независимый нелинейный ориентир с более случайным выбором порогов и поддерживает TreeSHAP. Параметры, версии библиотек, seed и обучающие даты записываются в отчёт. [Extra Trees](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.ExtraTreesRegressor.html) · [TreeSHAP](https://www.nature.com/articles/s42256-019-0138-9)

Зафиксированная модель учится на датах строго раньше `t0`. Её предсказания на `t0` и `t1` сохраняют одну базу и кодирование. Для деревьев вклад признака — сумма разностей TreeSHAP по общим наблюдениям. Для Ridge вклад равен изменению стандартизованного признака, умноженному на его коэффициент. Медианный прогноз даёт нулевые вклады. Для one-hot сумма вкладов закодированных столбцов показывается по исходной колонке.

```text
Cⱼ = Σᵢ [SHAPⱼ(xᵢ₁) − SHAPⱼ(xᵢ₀)]
ΔY_model = Σᵢ [f(xᵢ₁) − f(xᵢ₀)]
численная невязка = ΔY_model − Σⱼ Cⱼ
остаток = наблюдаемое изменение по общим ID − ΔY_model
фактическое изменение = новые + выбывшие + ΔY_model + остаток
```

Тест невязки проверяет аддитивность предсказания. Остаток показывает долю наблюдаемой разницы, которую модель оставила. Модель объясняет ассоциации. Для причинных выводов требуется отдельный дизайн исследования. [Алгоритм SHAP](https://papers.nips.cc/paper_files/paper/2017/hash/8a20a8621978632d76c43dfd28b67767-Abstract.html)

## Как читать диагностику

- **Локальный вклад** имеет знак и единицу целевой метрики. **Глобальная важность SHAP** — средний модуль вклада на конечную дату. **Перестановочная важность** — изменение MAE за пять перестановок на каждой дате проверки. Внутри даты общие для портфеля факторы переставить содержательно нельзя. Если есть минимум восемь отдельных проверочных дат и предшествующее обучение, целый блок общих факторов переставляется между датами для отдельной модели. Для рыночной кривой используются краткая и длинная ставки, уровень `(1y + 5y + 10y)/3`, наклон `10y − 1y` и кривизна `2×5y − 1y − 10y`. Для групп с `|r| ≥ 0,90` есть совместная перестановка. [Permutation importance](https://www.jmlr.org/papers/v20/18-760.html)
- **Нелинейность.** ALE на конечной дате строится на наблюдаемых диапазонах, до 12 квантильных интервалов и не менее пяти наблюдений в интервале. Сравниваются взвешенные линейное, квадратичное и кусочно-линейное приближения. Развороты и изменение наклона дают кандидатов на U-форму, порог, насыщение или изменение режима. Форма показывается при наличии поддержки и воспроизведении минимум в 70% из 40 повторных выборок внутри интервалов. Иначе вывод — «Тип зависимости не подтверждён». Для категорий показаны отдельные средние вклады. [ALE](https://arxiv.org/abs/1612.08468)
- **Взаимодействия.** Симметричная пара TreeSHAP учитывается как удвоенный внедиагональный элемент. Отчёт различает средний модуль на обе даты, изменение среднего подписанного вклада и сумму по портфелю, если есть вся совокупность. Выборка использует одни и те же ID, максимум 180 с ограничением по ширине кодирования. Повторная выборка даёт интервал силы. Для крупнейших 12 пар можно посмотреть вклады по наблюдаемым диапазонам и отдельным ID из той же выборки. Вклады пары уже входят в SHAP.
- **Проверка зафиксированной модели.** Для `t0` и `t1` показаны MAE, RMSE, R² при вариативной цели, смещение и ошибка суммы. Отдельно считается ошибка изменения суммы. Данные этих дат остаются проверочными. Expanding-window сравнение кандидатов проводится отдельно, до `t0`. [Временная валидация](https://otexts.com/fpp3/tscv.html)
- **Надёжность.** Для модельного вывода нужно минимум две обучающие даты, 40 строк и 8 общих ID. Статус «устойчиво» дополнительно требует как минимум два фолда выбора, победу над медианой на датах сравнения, приемлемые ошибку агрегата и остаток, отсутствие крупных сдвигов и предупреждений о взаимозависимых признаках. По умолчанию допустимы 35% относительно масштаба изменения, минимум 0,01 единицы метрики для ошибки суммы. Долю можно задать через `SPECTRUM_RESIDUAL_LIMIT`. Для знака используется bootstrap по общим ID (100 выборок), а для рейтинга — два повторных обучения на 80% обучающих ID с фиксированными seed. Эти проверки показывают чувствительность к изменению состава обучающей и проверочной выборок. Для статистического интервала банковского риска нужны отдельные данные и дизайн проверки.

## Привязка объяснений и выгрузок

Каждому отчёту присваивается `analysisId`. Смена дат, метрики или режима создаёт новую ревизию. Структурированный JSON содержит фактические числа, вклад, методы, источники и ограничения. DeepSeek получает только идентификаторы допущенных фактов; числовой вывод формируется сервером. Проверенный результат хранится с той же ревизией, а ответ на устаревший запрос отклоняется. При недостаточных данных объяснение ссылается на ограничение. [Инструкция подключения](../README.md#объяснения-и-deepseek)
