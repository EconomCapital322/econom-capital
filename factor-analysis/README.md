# «Спектр» · анализ портфеля

«Спектр» строит историю синтетических кредитных сделок, оценивает весь портфель по базовой и шести стрессовым кривым и объясняет изменение выбранного показателя между двумя датами. Команда 1 рассчитывает договорные платежи, команда 2 готовит рыночные кривые, команда 3 собирает результаты и выполняет факторный анализ.

## Первый запуск

1. Скачайте или клонируйте весь репозиторий `econom-capital`. Для расчёта нужны соседние каталоги `calculator`, `curves-module` и `factor-analysis`.
2. Запустите Docker Desktop. Для локального расчёта нужны Docker Compose 2.20+, Node.js, Python 3.11+ (рекомендуется 3.12), Make, CMake и компилятор C++20.
3. Запустите скрипт для вашей операционной системы из папки проекта:

**Windows (Командная строка cmd.exe):**
```cmd
cd factor-analysis
start.bat
```
*На Windows файл `start.bat` также можно запустить двойным щелчком в проводнике.*

**Windows (PowerShell):**
```powershell
cd factor-analysis
.\start.ps1
```

**macOS / Linux (или Git Bash на Windows):**
```sh
cd factor-analysis
./start.command
```
*На macOS файл `start.command` также можно открыть двойным щелчком.*

Откройте [«Спектр» на порту 8780](http://127.0.0.1:8780/). При первой установке скрипт создаёт Python-окружение `.venv` в корне проекта, ставит зависимости, собирает `cfcore` и запускает сервис кривых в Docker, если локальный API ещё недоступен. Для установки зависимостей, загрузки образов и новых рыночных дат нужен интернет.

Оставьте терминал открытым. Повторный запуск скрипта при работающем сервере откроет тот же экземпляр. При следующем запуске приложение откроет последний готовый расчёт, если он уже есть. Остановить локальный сервер можно через `Ctrl+C` в его терминале. Docker-сервисы имеют отдельный жизненный цикл.

## Первый расчёт

1. В боковом меню откройте **Портфель** и нажмите **Рассчитать портфель**. Начните с настроек по умолчанию. Это 120 исходных сделок, 16 новых в месяц, семь дат с 30 апреля по 30 октября 2026 года и код генерации `4317`.
2. Дождитесь готовности расчёта. В статусе отображаются отчётная дата, подготовка кривых и проверка рассчитанных сделок. Для проверки сервисов посмотрите блок **Подключения**.
3. В **Факторном анализе** сравните **NPV базы** за 30 сентября и 30 октября. Нажмите на **Остаток долга** на графике, затем откройте **Взаимодействия** и **Проверка модели**.
4. Откройте **Сценарии ставок**, выберите 30 октября и сценарий **Параллельный вверх**. При проверочном прогоне на эту дату рассчитано 216 сделок. Стоимость снизилась на 8,51 млн ₽ относительно базы. Внизу видно, какие сроки платежей дали этот эффект.
5. В **Портфеле** найдите сделку по ID и откройте её график платежей. В **Данных** за ту же дату скачайте ответ API кривых и отчёты калькулятора.

## Как связаны три команды

1. **Генератор команды 3** создаёт сделки по заданным распределениям. На каждой следующей дате добавляются новые ID и обновляется остаток по действующим сделкам по графику предыдущего расчёта. Один и тот же код генерации с теми же параметрами воспроизводит входной портфель.
2. **Калькулятор команды 1** получает нормализованный `calculator_input.csv` на одну дату. «Спектр» запускает ядро C++ `cfcore` и читает `cashflows.csv` с платежами и `deal_summary.csv` со сводкой по сделкам.
3. **Сервис команды 2** через `GET /api/v1/curve-runs/standard-result?reportDate=…` выдаёт базовую и шесть стрессовых кривых на ту же дату. Если готового ответа ещё нет, клиент запрашивает подготовку и ждёт результата. С каждой датой сохраняются идентификатор расчёта и контрольная сумма исходного ответа.
4. **Общий модуль дисконтирования** выбирает бакет по дате платежа и берёт готовый коэффициент дисконтирования (DF) из ответа кривых. Текущая стоимость платежа — сумма платежа, умноженная на DF. В семи сценариях меняются DF, платежи остаются теми же. Стоимость по сценарию суммируется по всем платежам всех сделок на выбранную дату. [Контракт оценки `calendar-bucket-v1`](../integration/CONTRACT.md)
5. **Аналитика команды 3** собирает таблицу с одной строкой на сделку и дату. В ней есть договорные параметры, значения рыночных кривых и рассчитанные целевые показатели. Из неё строятся отчёт, графики и пояснения.

## Что смотреть на каждом экране

| Экран | Что делать и как читать результат |
| --- | --- |
| **Портфель** | Задайте размер начальной выборки, ежемесячные выдачи, число дат и код генерации. В **Параметрах сделок и распределениях** можно изменить сумму, срок, ставку и доли схем выплат. Доли аннуитетных, дифференцированных и сделок с телом в конце в сумме дают 100%. Аналогично для долей фиксированных и плавающих. Плавающие ставки используют тестовый индекс и договорную надбавку. В **Составе портфеля** выберите дату и нажмите на ID сделки, чтобы увидеть суммы и даты платежей по основному долгу и процентам. |
| **Сценарии ставок** | Выберите отчётную дату и стресс. `ΔPV = PV стресса − PV базы`. Отрицательная ΔPV означает снижение стоимости относительно базы. Можно сравнить кривые и проверить, какие интервалы сроков (бакеты) сформировали общую ΔPV. Карточка срока показывает средний горизонт выплат, взвешенный по базовой PV. |
| **Факторный анализ** | Выберите даты и показатель, затем нажмите **Разложить изменение**. Встроенные цели включают NPV, ΔPV выбранного в генераторе стресса, проценты и полные договорные платежи за ближайшие 12 месяцев. NPV — сумма приведённых к отчётной дате будущих платежей по базовой кривой. |
| **Данные** | Посмотрите профиль таблицы, пропуски и диапазоны признаков. В **Настройке модели** можно выбрать целевую метрику и факторы. В **Источниках расчёта** видны число сделок, число строк денежных потоков, происхождение кривых и выгрузки за каждую дату. |

### Как читать факторный анализ

На графике **Что изменило показатель** конечное значение минус начальное складывается из значений метрики по новым сделкам, вкладов выбывших сделок, модельных вкладов по общим ID и необъяснённого остатка. Вклад выбывшей сделки равен её значению на начальную дату с обратным знаком. Модельные вклады рассчитываются методом TreeSHAP для случайного леса, обученного на датах до начала сравнения. По клику на столбец фактора видны его значения на обе даты и разброс вклада при повторной выборке сделок.

- **История метрики** показывает сумму показателя по каждому снимку портфеля.
- **Важность факторов** показывает изменение ошибки модели при перестановке признака и средний абсолютный вклад SHAP. Важность отражает силу связи, а знак на водопаде — направление вклада в конкретном сравнении.
- **Взаимодействия** показывает пары признаков с совместным эффектом. Этот эффект уже учтён в столбцах факторного графика.
- **Нелинейные эффекты** показывает, как меняется модельная оценка по диапазону числового признака (ALE), а для категорий — средний вклад по группе.
- **Проверка модели** сравнивает среднюю абсолютную ошибку (MAE) случайного леса, линейной модели и медианного прогноза на более поздних датах. Меньше — лучше.
- **Объяснение** отвечает на вопросы по готовому отчёту и ведёт к соответствующему графику. Попробуйте «Что сильнее всего повлияло на NPV?».

Вклады описывают связи в модели. Для причинного вывода нужна проверка гипотез. Основной результат проекта — сценарная оценка и разложение изменения показателей. Для итогового Economic Capital и полного NII нужна отдельная методика. [Методология и границы интерпретации](docs/methodology.md)

## Свой CSV и выгрузки

В **Данных** загрузите CSV в UTF-8 размером до 6 МБ и 20 000 строк. Нужна одна строка на пару «ID сделки и дата», числовая метрика без пропусков и хотя бы один меняющийся признак. Поддерживаются даты `YYYY-MM-DD` и `DD.MM.YYYY`. Выберите колонки даты, ID и метрики, отметьте признаки и нажмите **Пересчитать**. Для модельного разложения нужно не меньше двух дат до начала сравнения, 40 обучающих строк и 8 общих сделок на выбранные даты. При неполном снимке отсутствующий ID будет трактоваться как выбытие.

По умолчанию расчёты лежат в `factor-analysis/.local/runs/`. В каждом запуске `dataset.csv` содержит таблицу для анализа, `workspace.json` — результаты и параметры. В папке каждой отчётной даты есть вход калькулятора `calculator_input.csv`, результаты `core/` и исходный ответ `curves/standard-result.json`. Файлы `core/discounted_cashflows.csv` и `core/discounted_deal_summary.csv` содержат оценку по каждому платежу и сделке для семи сценариев. Готовые выгрузки также доступны в интерфейсе. Локальные результаты исключены из Git.

## Если расчёт не запускается

- **Старая версия Python.** Проверьте `python3 --version` или `python --version`. Если установленная версия 3.11 или новее доступна только по другому имени или пути, укажите её при первом запуске через `SPECTRUM_PYTHON`. Например, `SPECTRUM_PYTHON=python3.12 ./start.command` на Unix/macOS, либо `set SPECTRUM_PYTHON=python && start.bat` на Windows.
- **API кривых недоступен.** Проверьте, что Docker Desktop запущен и локальный API отвечает на порту 8000. Для другого экземпляра укажите `SPECTRUM_CURVES_URL`. При стандартных портах интерфейс команды 2 доступен на [порту 5173](http://127.0.0.1:5173/).
- **Ошибка TLS при загрузке с MOEX.** Сохраните официальный сертификат в `factor-analysis/.local/certs/moex-ca.pem` или задайте его абсолютный путь через `SPECTRUM_MOEX_CA` до первого запуска Docker. Скрипт монтирует сертификат в worker кривых. Для уже запущенного локального проекта пересоздайте worker командой ниже, затем повторите подготовку проблемной даты в интерфейсе кривых и запустите расчёт в «Спектре». [Инструкция Московской биржи](https://www.moex.com/n106155?nt=112)
- **Нет публикации за дату.** Выберите период с доступными публикациями. Если все нужные даты уже рассчитывались через API, можно включить **Использовать сохранённые рыночные кривые**. Для этого нужен полный ответ на каждую выбранную дату в `factor-analysis/.local/curves/YYYY-MM-DD.json`. Последний готовый расчёт можно открыть и при недоступном API.
- **Калькулятор собран в другом месте.** Укажите абсолютный путь к `cfcore` (или `cfcore.exe`) через `SPECTRUM_CFCORE`. Для занятого порта интерфейса задайте `SPECTRUM_PORT`, например `SPECTRUM_PORT=8781 ./start.command` (или `set SPECTRUM_PORT=8781 && start.bat` на Windows).

Обновление worker с официальным сертификатом для проекта `econ-spectrum-local`, из корня репозитория.

```sh
SPECTRUM_MOEX_CA="$PWD/factor-analysis/.local/certs/moex-ca.pem" \
  docker compose -p econ-spectrum-local \
  -f docker-compose.yaml -f factor-analysis/compose.moex-ca.yaml up -d --wait worker
```

### Локальная языковая модель

В базовой установке **Объяснение** использует факты из рассчитанного отчёта. На Apple Silicon можно подключить локальный Qwen через MLX. Из папки `factor-analysis` выполните следующее.

```sh
python3.12 -m venv .local/llm
.local/llm/bin/python -m pip install mlx-lm==0.32.2
./start.command
```

Если «Спектр» уже запущен, остановите его перед последней командой. При первом запуске MLX загружает веса модели. Другой локальный сервер можно задать через `SPECTRUM_LLM_URL` и `SPECTRUM_LLM_MODEL`. LLM получает вопрос и названия фактов, выбирает подходящие факты, а интерфейс подставляет числа и ссылки из готового расчёта.
