# «Спектр» · факторный анализ портфеля

«Спектр» отвечает на вопрос, почему изменилась стоимость портфеля между двумя датами. В **расчётном режиме** приложение сверяет договорные платежи и NPV с общим калькулятором и раскладывает изменение на потоки, дисконтирование и состав портфеля. В **ML-режиме** оно анализирует произвольную суммируемую метрику, оценивает вклад признаков и отдельно показывает необъяснённый остаток.

В меню **Внешний вид** можно сохранить тему, плотность, прозрачность, движение и оптику блика. **Cmd/Ctrl + K** открывает поиск по разделам и действиям, доступным в текущем расчёте. [Spectrum Glass 2.0](docs/spectrum-glass.md)

## Запуск

Для единого стека выполните `make spectrum-up` из корня `econom-capital` и откройте [Спектр](http://127.0.0.1:8780/). [Общий запуск и архитектура](../README.md)

Для самостоятельного расчёта нужны весь репозиторий, Python 3.11+, Node.js 22.12+ с npm, CMake 3.20+ и компилятор C++20. Скрипты запуска собирают встроенные кривые, если готовых файлов ещё нет. Первое получение зависимостей может потребовать интернет. Анализ и сохранённый отчёт доступны и при ошибке сборки.

После обновления проекта остановите прежний локальный сервер и запустите его снова. Если изменился исходный код React, пересоберите веб-модуль из корня репозитория.

```sh
npm --prefix curves-module/frontend ci
npm --prefix curves-module/frontend run build:embedded
```

### macOS, Linux или Git Bash

Для `start.command` нужен Make. На macOS запустите Docker Desktop, на Linux включите Docker Engine.

```sh
cd factor-analysis
./start.command
```

Откройте браузер на порту 8780. На macOS можно также открыть `start.command` двойным щелчком. Скрипт создаёт `.venv`, сверяет версии библиотек, при необходимости собирает `cfcore` и запускает сервис кривых. Окно терминала держит приложение открытым. `Ctrl+C` останавливает «Спектр». Данные расчётов и Docker-стенд сохраняются. [Открыть «Спектр»](http://127.0.0.1:8780/)

- Если `python3` указывает на старую версию, задайте путь к установленному интерпретатору, например `SPECTRUM_PYTHON=python3.12 ./start.command`.
- Если сервис кривых уже доступен, просто откройте «Спектр». Для другого адреса укажите `SPECTRUM_CURVES_URL`. Если калькулятор собран отдельно, укажите путь `SPECTRUM_CFCORE`.
- Для запуска без Docker и MOEX используйте `SPECTRUM_SKIP_CURVES=1 SPECTRUM_LLM_ENABLED=0 ./start.command`. В **Портфеле** выберите **Учебные кривые (офлайн)**. Сборка ядра и первая установка зависимостей могут потребовать интернет.
- Для расчёта по сохранённым ответам команды 2 выберите **Сохранённые рыночные кривые**. На каждую дату нужен полный официальный снимок `factor-analysis/.local/curves/YYYY-MM-DD.json`. При наличии готового портфеля можно открыть его сразу.

### Windows

Из корня репозитория запустите скрипт в командной строке.

```cmd
cd factor-analysis
start.bat
```

В PowerShell из корня репозитория выполните следующее.

```powershell
cd factor-analysis
.\start.ps1
```

`start.bat` также открывается двойным щелчком в Проводнике. Скрипты ищут Python в папке `.venv` и при необходимости создают окружение. Если установлен `uv`, для нового окружения используется Python 3.12. Для расчёта по учебным кривым откройте **Портфель → Учебные кривые (офлайн)**.

Для рыночных кривых запустите Docker Desktop с Linux-контейнерами и поднимите API команды 2 перед запуском `start.bat` или `start.ps1`. Выполните команды в PowerShell из корня репозитория.

```powershell
if (-not (Test-Path curves-module/.env)) {
    Copy-Item curves-module/.env.example curves-module/.env
}
docker compose up -d --wait api worker
```

### Запуск через Docker

Из корня репозитория выполните команду. Образ содержит `cfcore` и React-модуль кривых. Все разделы открываются на порту 8780.

```sh
make spectrum-up
```

Данные сохраняются в томе `spectrum_data`. Порт меняется через `SPECTRUM_DOCKER_PORT`. На Windows доступна [равнозначная команда PowerShell](../README.md#единый-запуск).

При ошибке TLS в worker MOEX сохраните официальный сертификат в `factor-analysis/.local/certs/moex-ca.pem` либо задайте `SPECTRUM_MOEX_CA`. Для уже поднятого стенда добавьте `-f factor-analysis/compose.moex-ca.yaml` к файлам Compose и пересоздайте `worker`. Для обработки новых дат API и worker должны использовать `AUTOMATION__ENABLED=true` из `curves-module/.env`. Затем повторите подготовку проблемной даты в интерфейсе команды 2. При отсутствии публикации за дату выберите доступную отчётную дату. [Инструкция MOEX](https://www.moex.com/n106155?nt=112)

## Сквозной показ

Сначала откройте **Кривые**. На готовой рыночной дате доступно действие **Использовать для оценки портфеля**. В конструкторе оно закрепляет Run ID за одной датой. Для уже рассчитанного портфеля действие открывает подтверждение переоценки. Старая ревизия сохраняет применённые кривые и доступные выгрузки. [Полный сценарий](../integration/DEMO.md)

1. В **Портфеле** нажмите **Создать тестовый портфель**. Стартовые параметры задают 120 исходных сделок, 16 новых в месяц и семь дат с 30 апреля по 30 октября 2026 года. Для автономного показа выберите учебные кривые. После расчёта откроется **Состав портфеля**. Выберите дату и нажмите на ID, чтобы открыть график платежей по сделке.
2. В **Анализе** нажмите **Изменить параметры**. Выберите **Расчётный анализ**, **NPV базы** и даты 30 сентября и 30 октября, затем нажмите **Рассчитать вклады**. По умолчанию открывается водопад. Кнопка **К вкладам** показывает горизонтальное сравнение. Нажмите на вклад для точной суммы и объяснения.
3. В **Подробном анализе** откройте **Денежные потоки**, чтобы разложить вклад на плановые платежи, перенос по срокам и эффекты изменения договора. Четыре комбинации потоков и кривых видны в **Методологии и выгрузках**.
4. В **Сценариях** выберите дату и один из шести стрессов. Таблица PV и разрез по срокам открываются отдельно под графиком. `ΔPV = PV стресса − PV базы` измеряется на одну дату. Кнопка **Разобрать изменение сценария** заполняет параметры для сравнения этой ΔPV между датами.
5. Для **Анализа зависимостей (ML)** смените режим через **Изменить параметры**. В **Подробном анализе** вкладка **Качество** показывает ошибки на обеих датах. В **Зависимостях** нажмите **Рассчитать детализацию** и выберите признак и вид графика ALE, SHAP, ICE или PDP. В **Взаимодействиях** пару можно выбрать на матрице.
6. Нажмите **Спросить AI** и откройте источник из ответа. Для вопроса о конкретном вкладе используйте **Объяснить с помощью AI** в панели фактора. В разделе **Данные → Источники расчёта** доступны входная выгрузка калькулятора, денежные потоки, кривые и PV за одну дату.

На телефоне широкие таблицы и графики можно листать внутри их области.

## Свои данные и экспорт

- **CSV для ML.** В разделе **Данные** выберите **Таблица CSV**. Задайте поля даты, ID, целевой показатель и единицу измерения. Нажмите **Проверить структуру**, проверьте факторы и запустите расчёт вкладов. Нужны уникальная пара «ID и дата» и суммируемый числовой показатель. Поддерживаются UTF-8, запятая, точка с запятой или табуляция, до 6 МБ, 20 000 строк и 80 колонок. Автоматический отбор до 16 факторов проводится по обучающему периоду. [Учебный CSV с нелинейностью и взаимодействием](examples/analysis.csv)
- **ZIP для расчёта.** В разделе **Данные** выберите **Снимки ZIP**. В **Источниках расчёта** можно скачать историю текущего портфеля и перенести её на другой стенд. Для вручную собранного архива в корне должны лежать папки `YYYY-MM-DD`, по одной на каждый снимок. Импорт поддерживает от 2 до 12 дат, 16 МБ архивированного и 96 МБ распакованного содержимого. Дополнительные поля исходного банковского файла сначала приводятся к нормализованной схеме. [Схема входных данных команды 1](../calculator/cf-normalizer/contracts/normalized-deals-v1.json)

```text
YYYY-MM-DD/
├── calculator_input.csv
├── core/
│   ├── cashflows.csv
│   ├── deal_summary.csv
│   └── discounted_deal_summary.csv
└── curves/standard-result.json
```

Для архива, экспортированного «Спектром», проверяется также `manifest.json` с датами, ID расчётов и SHA-256 кривых. Если дата, валюта, сторона, ID или стоимость расходятся, импорт выдаёт сообщение и оставляет последний готовый отчёт доступным. При неполном снимке пропавший ID учитывается как выбытие, поэтому проверьте состав выборки.

- **Подробный анализ → Методология и выгрузки** содержит автономный HTML, JSON текущей ревизии и CSV вкладов. После диагностики доступны CSV взаимодействий или детализации денежных потоков. Для ML есть CSV качества. JSON хранит параметры анализа. HTML и JSON содержат источники, ограничения и проверенное резюме, если пользователь его запросил. В CSV текстовые значения обрабатываются для открытия в электронных таблицах. Локальные снимки лежат в `factor-analysis/.local/runs/`.

## Объяснения и DeepSeek

Без AI приложение объясняет результат из проверенных фактов. Это режим по умолчанию в `.env.example`. Для подключения DeepSeek скопируйте `factor-analysis/.env.example` в `factor-analysis/.env.local`, задайте поля ниже и перезапустите приложение. Файл `.env.local` исключён из Git. Ключ можно задать в этом файле с правами `0600` или через защищённые переменные окружения. Для Compose используйте переменные процесса запуска.

```dotenv
SPECTRUM_LLM_PROVIDER=deepseek
SPECTRUM_ALLOW_EXTERNAL_LLM=true
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_API_KEY=
```

Кнопка **Спросить AI** открывает общий помощник для факторного анализа, готовых кривых, сценариев, рассчитанного портфеля и профиля данных. При ширине окна от 1180 px панель пристыковывается справа. Её ширину можно изменить перетаскиванием границы или стрелками с клавиатуры. В более узком окне помощник открывается поверх отчёта. Диалог и черновик восстанавливаются при возвращении к тому же фактору или сценарию в текущей ревизии.

**Новый диалог** очищает текущую беседу. **Отменить ожидание** прекращает показ ответа в интерфейсе. Запрос, уже принятый провайдером, может завершиться на его стороне.

Если в панели явно разрешена отправка, DeepSeek получает очищенный вопрос, проверенные агрегаты синтетического портфеля или публичных кривых и данные о связанных фактах. Допускаются даты, суммы и семантика разрешённых фактов. Исходный вопрос остаётся в локальном диалоге. Сервер отправляет только слова из разрешённого словаря и ссылки на факты текущего диалога. Сервис принимает только официальный HTTPS-адрес DeepSeek. Валидация проверяет знаки, сравнения, ранги, форму зависимости, статус проверки и ссылки. Даты и суммы в ответ подставляются из расчёта. [JSON Output DeepSeek](https://api-docs.deepseek.com/guides/json_mode/)

Загруженные CSV и ZIP по умолчанию обрабатываются локально. Для разрешённых организацией агрегатов оператор может задать `SPECTRUM_AI_BANK_FIELDS` в серверном окружении или Compose. Допустимые значения перечисляются через запятую:

- `metric.start`, `metric.end`, `metric.change`, `composition.added`, `composition.removed`, `validation.reconciliation`, `model.residual`
- `data.profile`, `data.missing`, `data.outliers`, `data.history`
- `factor.direction` для знаков вкладов с псевдонимами факторов

В ограниченном режиме уходят только перечисленные агрегаты или направления. Имена колонок, сделки, договоры, даты, единицы и исходная переписка остаются локально. Разрешение в панели требуется и при настроенной политике. Резюме для загруженных данных формируется локально.

В анализе нажмите **Сформировать аналитическое резюме**. После проверки оно сохраняется для текущей ревизии. Флажок **Включить сохранённое резюме в отчёт** в **Подробный анализ → Методология и выгрузки** управляет экспортом HTML и JSON. Загрузка страницы использует сохранённую копию без сетевого запроса к модели.

Для доступной локальной модели укажите `SPECTRUM_LLM_PROVIDER=local`, `SPECTRUM_LLM_URL` и `SPECTRUM_LLM_MODEL`. На Apple Silicon `start.command` может запустить подготовленный `mlx-lm` из `.local/llm`. Сохраните `SPECTRUM_LLM_ENABLED=0` для запуска с проверенными фактами без обращения к модели.

После настройки ключа и разрешения владелец может разово проверить реальный API из папки `factor-analysis`. Запуск с `--live` делает запрос по синтетическому отчёту и может расходовать баланс. Обычные тесты используют подмену сетевого клиента.

```sh
../.venv/bin/python -m service.deepseek_smoke --live
../.venv/bin/python -m service.deepseek_smoke --live --case ml
```
